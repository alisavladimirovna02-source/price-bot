# Одновременная обработка прайсов

Разрешённые пользователи могут отправлять и обрабатывать прайсы параллельно.
Команды одного пользователя сохраняют свой порядок. Нажатие «Обработать»
фиксирует текущие позиции и запускает фоновую задачу; новые сообщения остаются
для следующего прайса. Повторное нажатие во время работы не создаёт дубликат.

Для каждого прайса создаётся отдельный постоянный каталог:

```
/data/reports/users/<telegram_user_id>/<chat_id>/jobs/<job_id>/
```

В нём находятся входной JSON, итоговый CSV, ненайденные товары и отчёты МВЦ.
Файл `latest.json` в каталоге пользователя указывает на последний завершённый
результат. Кнопка «Не найдено» использует только этот результат, включая после
перезапуска контейнера. Старые общие отчёты не удаляются, но не показываются
произвольному пользователю: после обновления нужно обработать свой прайс.

Парсер работает отдельным асинхронным subprocess с таймаутом 180 секунд.
Сетевые проверки МВЦ и GitHub выполняются вне основного event loop. Общий
снимок предыдущих МВЦ защищён блокировкой; файлы результатов МВЦ разделены
по задачам. Запись mapping по-прежнему использует существующее подтверждение
и защиту от конфликтов GitHub.

Проверка: `python3 -m unittest discover -v`. Дополнительные сценарии в
`test_price_jobs.py` проверяют одновременный запуск двух пользователей,
доступность `/start` во время работы, отсутствие смешивания документов,
сохранение новых позиций, повторные кнопки, ошибку одной задачи и таймаут
реальных subprocess.

В логах каждая обработка имеет `job`, `user_id`, длительность и признак
успешного завершения. Параллельность устраняет ожидание чужого обработчика;
скорость самих расчётов и сетевых запросов зависит от ресурсов VPS и внешних
сервисов.
