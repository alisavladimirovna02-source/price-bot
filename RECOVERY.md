## Работа без Registry

Registry полностью отключён в рабочем боте: кнопки и команды для него убраны,
обработчик прайсов и пополнение mapping не обращаются к `bot.db` или каталогу
SKU. Архивная база оставлена в `data-backup-20260925/` только как резервная
копия. Старые модули Registry не участвуют в запуске.

Источник сопоставлений — `mapping.txt` в GitHub. Бот принимает только точные
однозначные соответствия после нормализации пробелов, регистра и знаков.
Автоматический подбор по похожему названию отключён. Неизвестные названия
попадают в «Не найдено»; повторяющиеся названия с разными SKU показываются
как конфликт. Для добавления соответствий администратор нажимает
«➕ Пополнить mapping», отправляет строки `название поставщика = SKU` и
подтверждает предпросмотр. Перед сохранением бот повторно проверяет GitHub и
сохраняет весь пакет одной записью. Конфликтные пакеты не сохраняются.

Такой режим позволяет работать без восстановленной `bot.db`, но требует
внимательной проверки администратором новых соответствий: бот больше не
сверяет характеристики товара с каталогом SKU.

## Перенос на VPS с Docker Compose

1. Перенесите эту папку на VPS. `bot.db` для запуска не нужна.
2. Скопируйте `.env.example` в `.env` и заполните `TOKEN`, `ADMIN_USERS`,
   `GITHUB_TOKEN` и необходимые токены WB. Файл `.env` не публикуйте в GitHub.
3. Запустите `docker compose up -d --build`. Проверить запуск можно командой
   `docker compose logs -f price-bot`.

Каталог `./data` хранит локальный `mapping.txt`, а `./data/reports` — рабочие
файлы и отчёты обработки прайсов. Они сохраняются при пересоздании контейнера.
При обработке прайса бот читает актуальный mapping из GitHub; для этого токен должен иметь
доступ к репозиторию. Для сохранения новых сопоставлений нужны права записи.
В Railway нужен постоянно работающий сервис из Dockerfile и постоянный том
в `/data`; переменные из `.env.example` задаются в настройках сервиса.
